# tianxia.kr UI/UX 리뉴얼 스펙

> 이 문서는 Claude Code 작업 지시서다. 코드 작성 전 반드시 전체를 읽고, **Phase 0부터 순서대로** 진행한다.

---

## 0. 전제

- **에셋은 이미 리포지토리에 존재한다.** 히어로 영상, 브랜드 로고, 타이포그래피 영상, KOL 레퍼런스, 구프 영상 모두 기존 파일을 재사용한다. 새 에셋을 생성하거나 플레이스홀더를 만들지 않는다.
- **이번 작업 범위는 UI/UX 레이어뿐이다.** 데이터 소스, API, CMS 구조, 라우팅은 건드리지 않는다.
- 작업 시작 전 다음을 먼저 파악하고 요약 보고한다:
  - 기존 디자인 토큰(색상, 타이포 스케일, spacing) 정의 위치
  - 현재 사용 중인 애니메이션 라이브러리 (framer-motion / GSAP / CSS)
  - 기존 영상·이미지 에셋의 실제 경로와 포맷
- **기존 토큰과 폰트를 그대로 쓴다.** 새 팔레트나 새 폰트를 임의로 도입하지 않는다. 필요하다고 판단되면 먼저 물어본다.

## 1. 실행 규칙

- `feat/ui-refresh` 피처 브랜치에서 작업한다.
- **Phase 단위로 멈춘다.** 각 Phase 완료 후 변경 파일 목록과 확인 방법을 보고하고, 승인 전까지 다음 Phase로 넘어가지 않는다.
- **푸시는 명시적으로 "푸쉬해"라고 지시받았을 때만 한다.** 자동 푸시 금지.
- 커밋은 Phase 단위로 나눈다.

## Phase 0 — 인트로 로더

레퍼런스: [dg-cinema.com](https://www.dg-cinema.com/en) 진입 연출

사이트 진입 시 숫자가 올라가면서 화면이 전환되는 연출. **이 페이지에서 가장 강한 순간이므로 여기에 힘을 몰아준다.**

**동작**

1. 전체 화면 오버레이가 최상단에 깔린다 (`position: fixed`, `inset: 0`)
2. 카운터가 0에서 100까지 상승. 등가속이 아니라 **초반 빠르게 → 후반 감속** (ease-out)
3. 100 도달 후 짧은 정지(약 200ms), 이어서 화면 전환으로 히어로 노출

**구현 요구사항**

- 카운터 숫자는 `font-variant-numeric: tabular-nums` — 자릿수 바뀔 때 흔들리면 안 된다
- 진행률은 **실제 로딩과 연동**한다: 히어로 영상의 `canplaythrough` 또는 `document.readyState`를 기준으로 삼되, 최소 1.4초 / 최대 3초로 clamp. 실제 로딩이 빨라도 최소 시간은 채우고, 느려도 3초에서 강제 종료한다
- 전환은 `clip-path` 또는 `transform` 기반 wipe 한 가지만 쓴다. 페이드 + 스케일 + 블러를 겹쳐 쌓지 않는다
- 로더가 떠 있는 동안 `body` 스크롤 잠금, 해제 시 원복
- **콘텐츠 렌더를 지연시키지 않는다.** 본문은 정상적으로 DOM에 렌더되고 오버레이가 그 위를 덮는 구조여야 한다 (SEO·LCP 보호)
- `sessionStorage`로 세션당 1회만 재생. 재방문 시 스킵
- `prefers-reduced-motion: reduce`면 로더 자체를 건너뛴다
- Next.js 하이드레이션 주의: 카운터 초기값은 서버·클라이언트가 동일해야 한다. 애니메이션은 `useEffect` 이후 클라이언트에서만 시작

**하지 말 것**

- 실제 로딩과 무관하게 항상 고정 시간 동안 도는 가짜 로더
- 로더 안에 로고·슬로건·부가 문구를 채워넣는 것. 숫자와 전환만으로 충분하다

## Phase 1 — Hero

레퍼런스: [tigranz.com](https://tigranz.com) `#home`

기존 자체 영상을 풀블리드로 배치한다.

- `<video muted autoPlay playsInline loop preload="metadata">` + `poster` 필수
- poster 이미지는 `priority`로 선로드 (LCP 대상)
- 모바일: 자동재생이 차단되거나 데이터 부담이 큰 환경을 고려해 poster 우선 표시, 세로 크롭 대응
- 영상 위 텍스트가 있다면 가독성 확보용 그라디언트 오버레이. 단색 반투명 판때기로 덮지 않는다
- 네비게이션은 원페이지 앵커 구조: `#home / #work / #about / #contact`

## Phase 2 — 브랜드 로고 마퀴

기존 로고 에셋을 한 줄로 빠르게 흘려보낸다.

- CSS `transform: translateX()` 기반 무한 루프. `left`/`margin` 애니메이션 금지 (리플로우 발생)
- 리스트를 2벌 복제해 이어 붙여 끊김 없이 순환
- `will-change: transform`, GPU 합성 유지
- 호버 시 일시정지
- `prefers-reduced-motion: reduce`면 정지된 정적 그리드로 대체
- 로고는 높이 기준으로 정렬한다. 폭이 제각각인 로고를 같은 박스에 강제로 맞추면 비율이 깨진다

---

## Phase 3 — 타이포그래피 영상

직접 제작한 타이포그래피 영상을 독립 섹션으로 배치한다.

- 뷰포트 진입 시 재생, 이탈 시 정지 (`IntersectionObserver`, threshold 0.4 내외)
- **스크롤 스크러빙(스크롤 위치에 프레임 연동) 하지 않는다.** 모바일에서 비용이 크고 끊긴다
- 이 섹션 위에 다른 텍스트를 겹치지 않는다. 영상 자체가 콘텐츠다

---

## Phase 4 — Work

KOL 레퍼런스 + 구프 영상을 함께 배치한다.

- 그리드. 데스크톱에서 호버 시 무음 프리뷰 재생, 이탈 시 정지 후 poster 복귀
- 모바일은 호버가 없으므로 poster + 탭 재생
- 모든 영상 `preload="none"`, 뷰포트 진입 시점에 로드
- 카드가 6개를 넘으면 초기 로드는 앞쪽만, 나머지는 지연 로드

## 공통 요구사항

**성능**

- 한 페이지에 영상이 여러 개 들어간다. 히어로만 초기 로드, 나머지는 전부 지연 로드
- 동시에 재생 중인 영상은 최대 1개로 제한한다
- 각 Phase 후 Lighthouse 모바일 점수를 확인하고, LCP·CLS 수치를 보고한다

**접근성**

- `prefers-reduced-motion: reduce` 전 구간 대응 (로더 스킵, 마퀴 정지, 자동재생 억제)
- 키보드 포커스 링 유지. 오버레이 요소는 `pointer-events: none`으로 포커스 트랩을 만들지 않는다
- 앵커 네비게이션은 키보드로 이동 가능해야 한다

**모션 원칙**

- 강한 연출은 인트로 로더 하나로 충분하다. 모든 섹션에 fade-and-slide-up 등장 효과를 붙이지 않는다 — 전형적인 템플릿 티가 난다
- 스크롤 진행률·시계 같은 HUD 요소는 이번 범위에서 제외한다 (필요해지면 별도 논의)

**지양할 것**

- 섹션마다 대문자 라벨(`OUR WORK` 같은) 얹기
- 내용이 순서가 아닌데 `01 / 02 / 03` 번호 붙이기
- 버튼·링크 텍스트 뒤에 화살표 문자 붙이기
- 모든 요소에 동일한 border-radius와 회색 그림자를 일괄 적용하기
